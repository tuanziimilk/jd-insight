# 标杆问题集

改了提示词、检索逻辑或意图规则之后，**同一批问题重跑，逐条 diff，重点看变坏的**。
只看「整体感觉变好了」会漏掉「涨了整体、坏了某一类」。

判定列填 ✅ / ⚠️ / ❌，并写清**错在哪一环**（意图 / 检索 / 生成），这样才知道该修哪里。

新发现的 bad case：（写在这里，然后补进上面的表）

**新发现的 bad case 一定要补进这张表**——否则同一个错会反复出现，
修好了下次改动又坏，谁也不知道。

## 已修的 bad case（留档，防回归）

### BUG-001 · 槽位跳过导致死循环（v2.0 → v2.0.1）

**现象**：简历诊断时点「跳过」→ 卡片消失 → **立刻又弹出同一张卡片**，无限循环。

**根因**：跳过后重新调 `ask()` 时传了 `force: true`，但 `ask()` 内部的槽位检查

```js
const missing = (intent.slots || []).filter((s) => !PROFILE[s]);
```

**完全没读这个参数**——`PROFILE.resume` 仍为空，所以 missing 仍非空，又走进 `askSlot`。

**修法**：

1. 槽位检查读 `opts.force`：`const missing = opts.force ? [] : (...)`
2. 顺带把降级信息传进系统提示（`opts.degraded`），让模型在开头就说明
   「因为没有简历，以下只能基于 JD 泛泛地说」，**而不是假装结论可靠**

**这条 bug 的教训（比 bug 本身重要）**：

> 它在标杆集里原本被标成 **✅** —— 但那个 ✅ 是**"我觉得应该没问题"**，不是真跑过。
>
> **没实际验证的项不许标 ✅。** 宁可留 ⬜ 待测，也不要假通过 ——
> 假通过的标杆集比没有标杆集更危险，因为它让你误以为有回归保护。
