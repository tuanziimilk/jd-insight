# JD Insight · 求职情报台

> 在你自己浏览的岗位详情页一键存下 JD，然后**用对话问它**：
> 这批岗位最高频的要求是什么、我的简历缺什么、面试会追问我什么。

一个给转型求职者做的 Chrome 扩展 + 本地分析脚本。没有服务器，数据只在你自己的浏览器里。

---

## 它解决什么问题

投简历前你想知道三件事，但没人告诉你答案：

| 问题 | 常见做法 | 这个工具怎么答 |
|---|---|---|
| 简历该突出什么？ | 凭感觉猜关键词 | 统计 15 个能力组在 N 条真实 JD 里的**覆盖率**，≥50% 的必须写进简历 |
| 我最该补什么能力？ | 什么都想学 | **覆盖率高 × 你标了空白** = 缺口排行，按火苗排序 |
| 报价定多少？ | 参考网上帖子 | 你采集样本的薪资带中位数 |

顺带回答：**该做哪个方向的 demo**（按岗位分型占比）、**面试会问什么**（按 JD 共性追问）。

## 三个部分

```
存 JD（扩展）  →  对话问它（侧边栏 AI）  →  批量出报告（Python）
   Alt+S            Alt+A                  python analyze_jd.py
```

- **采集**：只读你已经打开的页面，不自动翻页、不发请求
- **对话**：以你采集的 JD 为知识库，支持多轮、会追问缺失信息、答案带 JD 编号可回溯
- **报告**：能力覆盖率 / 缺口排行 / 薪资带 / 岗位分型 / 高频词 Top 25

## 快速开始

### 1. 装扩展（一分钟）

1. Chrome 打开 `chrome://extensions`
2. 右上角开 **开发者模式**
3. **加载已解压的扩展程序** → 选本仓库的 **`extension/`** 目录
4. 把「JD Insight」固定到工具栏

### 2. 采集

打开招聘网站，**点开某个岗位的详情页**，点右下角「+ 存 JD」或按 `Alt+S`。

> 薪资如果被网站的字体反爬挡住，会弹一次输入框让你照屏幕填，**直接回车跳过也行**。

建议攒 **15~20 条**再看结论，少于 10 条统计不稳。

### 3. 问它（可选，需要 API Key）

按 `Alt+A` 或点扩展图标里的「💬 打开情报台」。

首次使用点 ⚙ 配一个模型——支持任何 **OpenAI 兼容**端点：

| 预设 | 说明 |
|---|---|
| DeepSeek | 便宜、中文好，推荐起步 |
| OpenAI | `gpt-4o-mini` 够用 |
| Moonshot / 通义 | 国内直连 |
| 本地 Ollama | 免费，`http://localhost:11434/v1` |

**没有 Key 也能用**——「统计」类问题走确定性计算，不经模型。

### 3.5 打标与限定范围

在扩展弹窗的 JD 列表里，每条下方有两个可点切换的小标签：

- **意向**：未定 → 🔥 想投 → 👀 观察 → ❌ 不考虑
- **状态**：未投 → 已投 → 面试中 → 已挂 → 已拒

打完标后，情报台顶部的下拉可以**限定回答依据的范围**——
选「只看 🔥 想投」，之后的检索和统计就只看这些 JD，范围外的完全不参与。

> 刻意**不在采集时问标签**：采集要一次点击不打断浏览，标签是回头整理时才需要的东西。

### 3.6 花了多少钱

每条回答下方显示这次的 token 数和估算花费，顶部显示本会话累计，
设置页能看到累计总量并重置。

单价在设置页可配（默认填 DeepSeek 参考值）——**各厂价格随时变，所以不硬编在代码里**。
端点不返回 usage 时按字符数估算，并在界面标注「⚠ 估算」。

> 为什么做这个：PRD 里把「效率成本」列为四层指标之一。
> **指标不显示出来就是空话**——你不会为一个看不见的数字做优化。

### 4. 出报告

```bash
cd analyzer
cp config.example.py config.py     # Windows: copy config.example.py config.py
# 编辑 config.py 里的 MY_PROFILE，填你自己的能力现状
python analyze_jd.py
```

报告输出到 `reports/jd_report.md`。无第三方依赖，Python 3.8+ 即可。

## 设计决策

这个项目的重点不在代码量，在几个**刻意做出的取舍**。

### ① 扩展不做精确字段解析，只负责抓干净文本

招聘站是单页应用、class 名会变，写死选择器的扩展几周就废。所以：

- 字段提取放在 **Python 侧**——改规则比改扩展、重装、重启浏览器容易得多
- 扩展**永远额外存一份整页纯文本兜底**：即使选择器全部失效，数据也不丢，界面会标「⚠ 正文没抓准，已存整页文本兜底」

> **不可逆的损失要避免，可修的错误可以容忍。** 抓不准可以回头重新解析，抓漏了就永远没了。

### ② 统计类问题不进模型

「有几条 JD 要求 Discord」这种问题，规则算比模型算**更快、免费、可复现，而且不会算错**。
所以意图识别是**规则先行、模型兜底**，界面上会标出这一轮是 `rule:` 还是 `model` 判定的。

### ③ 不用向量检索

语料是几十到几百条同垂类 JD，词汇高度重叠。关键词打分 + 字段加权（标题权重 3、公司 2.5、正文 1）召回质量已经够，而向量要付：每条一次 embedding 调用、浏览器里维护索引、必须先配 Key 才能检索。

**语料上千条或需要跨语言语义匹配时再上。** 先问「确定性方案够不够」，不够才加不确定的那层。

### ④ 缺信息就追问，不猜

简历诊断需要「简历」这个槽位。没有就弹卡片要，**不基于空气诊断**。
用户也可以跳过——那时会明确告诉他「结论会弱很多」，而不是假装答得很好。

### ⑤ 涉及事实的改写必须人工确认

经历改写的系统提示里写死：**不许编造或修改任何数字、公司名、职位名、时间**，需要用户补的地方输出 `【需你确认：xxx】`，界面把它高亮成待办。

> AI 可以改措辞，但**不能替你编经历**——这是求职工具的底线。

### ⑥ Key 由用户自己持有

没有任何服务器。Key 存在浏览器本地，只发给用户自己填的 `base_url`。
不做托管代理，因为那意味着我要替所有使用者付账单，且他们的简历和 JD 会经过我的机器。

代价写在设置页里：**能物理接触这台电脑的人可以读到 key**，共用电脑请用低额度专用 key。

### ⑦ 权限最小化

只申请 `storage` + `downloads` + `sidePanel`，`host_permissions` 只列了 5 个招聘站，
调模型用的域名放在 `optional_host_permissions`（用户配了才请求授权）。
没有 `tabs`、没有 `<all_urls>`。

## ⚠️ 使用边界（重要）

**这个工具是辅助你自己的浏览行为，不是替你浏览。**

- ✅ 只读取你已经打开、已经渲染出来的页面内容
- ✅ 不发任何网络请求抓数据、不自动翻页、不模拟点击、不绕验证码
- ✅ **不破解字体反爬**——薪资被自定义字体挡住时，交给人补，而不是去还原字形映射

- ❌ 不要拿它做批量自动采集
- ❌ 不要高频操作

即便如此，**自动化提取内容仍可能落在平台用户协议的约束范围内**。
如果你正用这个账号求职，请记住：**账号比数据重要。** 正常速度浏览，顺手存你真的在看的岗位。

各站点的服务条款以站点公布为准，使用者自行负责（见 LICENSE 附加声明）。

## 隐私

**没有服务器，没有遥测，没有分析脚本。** 数据分三处，全在本地：

| 存在哪 | 内容 | 谁能看到 |
|---|---|---|
| `chrome.storage.local` → `jds` | 采集的 JD | 只有你 |
| `chrome.storage.local` → `profile` | 你粘贴的简历 | 只有你 + 你选的模型厂商 |
| `chrome.storage.local` → `llm` | base_url / model / key | 只有你 |
| 仓库 `data/` `reports/` | 导出文件与报告 | 只有你（已 `.gitignore`） |

`analyzer/config.py`（你的能力自评）和 `data/`、`reports/` 都不会进版本库。
