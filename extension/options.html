关于你的 Key：它只存在这台电脑的浏览器本地存储里，只会发给你自己填的 base_url。 本项目没有任何服务器，我看不到你的 key，也看不到你的 JD 数据。

How to use

怎么存一条 JD

  1. 在 BOSS 直聘的岗位列表里，鼠标在某张岗位卡上停一下（约半秒）。 停留是采集器判断"你在看哪一条"的唯一依据——列表上有十几张卡， 猜错就是存下一条你没看过的岗位。
  2. 点页面上的「存 JD」悬浮按钮，或按 Alt+S。 面板不是你停留那条的话，它会先自动切过去再存。
  3. 那个悬浮按钮可以拖到任意位置，拖一次就记住， 以后每个页面都在那儿。

薪资在列表页上是私有区字体（页面文本里读不到数字），采集器会现场 比对字形还原。还原不了就显示「＋薪资」，点一下原地手填。

条目下面那排小标签

意向（未定 / 想投 / 观察 / 不考虑）和投递状态 （想投 → 已投 → 进面 → 复面 → offer → 已挂 / 已拒）都是点一下循环切换， 情报台里能按它们筛选。深绿色那个是薪资，点开可以改。

导出后怎么跑分析脚本

  1. 在弹窗里点「jd_raw.txt」导出。
  2. 把文件放到 career-knowledgebase/05-资源库/JD原始数据/。
  3. 运行 99-脚本/analyze_jd.py，出高频要求的汇总报告。

如果你已经配好下面的云端同步，这条链路可以不用—— 同步之后直接在 career-os 工作台里看，那边有匹配分析。

Cloud Sync

同步到 career-web 工作台用的同一套 Supabase 项目。 不装 SDK，手写基于 fetch 的客户端——和上面调模型是同一套零构建原则。

两个值都在 career-web 的 .env.local 里，或 Supabase Dashboard → Settings → API 里能找到。anon key 可以公开——权限完全由数据库的 RLS 决定。

用邮箱+密码登录，不用魔法链接——魔法链接的回调要处理跳转到扩展页面， 在 MV3 里要绕一圈，对个人工具不值得。需要先在 career-web 里登录一次， 然后用「设置同步密码」功能给这个账号加一个密码（同一账号，RLS 按身份判断， 跟你用哪种方式登录无关）。

只做 upsert，不做删除——本地删记录不会同步删云端，避免网络抖动导致 的空列表被误当成「真的清空了」而级联删掉云端数据。
